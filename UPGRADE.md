# Upgrading from 1.x to 2.0

Version 2 requires PHP 8.3 or later. Both adapters implement `Psr\SimpleCache\CacheInterface` directly. Existing `new Cache($adapter)` calls still work. `Cache` is now a readonly class, so a subclass must be declared `readonly` as well. The wrapper also accepts any other PSR-16 implementation. Existing custom adapters can continue to implement `Solo\Cache\Adapter\CacheAdapterInterface`, which now extends the PSR interface.

1. **Rename keys containing `:`.** Use a collision-free mapping appropriate to your application. For example, `user:42:profile` can become `user.42.profile` if that key is available. PSR-16 reserves colons in item keys. Redis namespace prefixes can still contain them. Keys ending in a newline are also rejected. Redis `clear()` skips keys with a `:` after the prefix, so delete legacy colon keys yourself or switch to a fresh prefix.
2. **Start the file cache in a fresh directory.** Version 2 uses `solo-<sha256>.cache` filenames. A 1.x process can delete unrelated files when it calls `clear()`, so keep each version in its own directory during a rolling deployment. Allow the new cache to warm and retire the old directory once all 1.x workers have stopped. Schedule `gc()` to remove stale entries from the new directory. Version 2 creates the directory with mode `0700` and entries with mode `0600`, so every process that uses the pool must run as the same OS user.
3. **Check the Redis connection and namespace.** Supply a dedicated client in atomic mode with native prefix, serializer and compression disabled. The adapter validates these settings. An empty adapter prefix is invalid. A prefix without a trailing `:` gains one, so `catalog` now stores `catalog:item` instead of `catalogitem`. A fresh prefix such as `catalog-v2:` provides a clean cutover. The default `cache:` and the serialized value format remain compatible for valid item keys.
4. **Check failure handling.** The `MODE_THROW` and `MODE_FAIL` constants are replaced by the `Solo\Cache\Adapter\ErrorMode` enum, which the constructors and `setMode()` accept. Use `ErrorMode::Fail` for optional caches where I/O failures should fall back. In `ErrorMode::Throw`, failed storage operations raise the package cache exception. Invalid keys or Redis client options throw in either mode. Corrupt or expired entries are cache misses. Cached `null` is retained and `has()` returns `true` for it.
5. **Review bulk calls using numeric indexes.** `setMultiple([123 => $value])` writes the key `'123'`. PHP converts decimal string array keys to integers, so this also supports `['123' => $value]`. `getMultiple()` and `deleteMultiple()` still require lists of strings. Invalid keys are rejected before any part of the batch is applied. Backend failures can still result in partial writes for multi-command operations.
